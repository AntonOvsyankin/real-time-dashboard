# Real-time market dashboard

Take-home task for a Senior Frontend Developer role: an Angular 22 app that shows live market metrics for fictional instruments. The market data is generated by our own Rust library compiled to WebAssembly, running in a Web Worker. There is no backend; everything runs in the browser.

**Before changing architecture, data flow, the worker protocol or the Wasm interface, read `.claude/knowledge/architecture.md`.** It explains the design, the rules that must not break, and why each decision was made.

## Commands

| Command | What it does |
|---|---|
| `npm start` | Builds the Wasm (`build:wasm`), then `ng serve` on http://localhost:4200 |
| `npm run build` | Builds the Wasm, then the production Angular build into `dist/real-time-dashboard/browser` |
| `npm run build:wasm` | `cargo build --release --target wasm32-unknown-unknown` and copies the `.wasm` into `public/wasm/` |
| `npm run test:all` | `cargo test` (Rust) and then Vitest once (`ng test --watch=false`) |
| `npm run test:wasm` / `npm run test:ci` | Rust tests only / Angular tests only |

Run `npm run test:all` after any change; all tests must pass.

## Stack

- Angular 22, TypeScript 6 (strict), standalone components, signals, zoneless, OnPush, Signal Forms (`@angular/forms/signals`), plain SCSS, Vitest via `@angular/build:unit-test`
- Rust (edition 2021), target `wasm32-unknown-unknown`, no crates, no wasm-bindgen; hand-written `extern "C"` exports
- GitHub Actions deploys to GitHub Pages on every push to `main` (`.github/workflows/ci-deploy.yml`)

## Layout

- `src/app/core/models/` — data contracts shared by the app and the worker
- `src/app/core/producer/` — worker, worker logic (`ProducerEngine`), Wasm loader, `ProducerService`
- `src/app/core/metrics/` — metric formulas and `MetricsAccumulator`
- `src/app/core/settings/` — Signal Forms schema
- `src/app/core/utils/` — small framework-free helpers (usable in the worker)
- `src/app/features/dashboard/`, `src/app/features/settings/` — the two pages
- `src/app/shared/format/` — display formatting and pipes
- `wasm/market-generator/src/` — Rust crate: `rng.rs`, `generator.rs`, `lib.rs` (FFI exports)

## Rules

- **The user is learning Rust.** Keep Rust code plain and explicit: simple loops and `match`, no custom macros, no unnecessary traits or generics, and doc comments that name the Rust concept being used. Any `unsafe` stays in `lib.rs` with a `// SAFETY:` comment (currently there is none). When you write or change Rust, offer to explain it in TypeScript terms.
- Files in `core/models`, `core/instruments`, `core/metrics`, `core/utils` and the worker-side files in `core/producer` must not import from `@angular/*`; they run inside the worker.
- Tests must not use real timers or waits: use the injected `Scheduler` or `vi.useFakeTimers()`.
- Don't commit or push without the user's approval.
- Components hold no exported types or module-level helpers: types go to model files (`core/models`, or a feature-level file when they depend on Angular), shared helpers to `shared/format` or `core/utils`.
- Anything that must survive for future sessions belongs in this file or in `.claude/knowledge/`.

## Environment gotchas (Windows)

- Node 24 LTS. The global Angular CLI is an older version, so use `npx ng` or the npm scripts, not a global `ng`.
- Git Bash rewrites arguments that start with `/` into Windows paths (for example `--base-href /real-time-dashboard/`). Use `MSYS_NO_PATHCONV=1` or PowerShell.
- Git Bash here aliases `rm` to `rm -i` and has `noclobber` set; use `rm -f` and `>|`.
- `npm start` runs in the foreground; a background dev server must be fully stopped (including its `node` child) so it does not keep port 4200 busy.
